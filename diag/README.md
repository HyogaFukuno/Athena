# Athena 診断キット

動いている Athena のサーバーを、止めずに数時間測り、何をどう変えるとよいかを HTML のレポートにまとめる道具です。

| ファイル | 動かす場所 | 役割 |
|---|---|---|
| `athena-diag.sh` | 相手のサーバー（Linux） | 測って、結果を `athena-diag-<サーバー名>-<日時>.tar.gz` にまとめる |
| `athena_diag_report.py` | こちら（Python 3、追加のライブラリ不要） | tar.gz を読んで、HTML のレポートを作る |
| `RULES.md` | — | レポートが出す提案と、その基準の一覧（相手に説明するとき用） |

## 1. 相手にやってもらうこと

1. `athena-diag.sh` をサーバーのマシンに置く。
2. プレイヤーがいる時間帯を含めて、3時間ほど測る（root か、サーバーを動かしているユーザーで実行）。

   ```bash
   sudo ./athena-diag.sh --dir /opt/mc/arena1 --duration 3h
   ```

   - サーバーは止まりません。再起動も、コマンドの入力も、プラグインの追加も要りません。
   - `Ctrl-C` で早めに終えても、そこまでの分はまとめて保存されます。
   - ssh を切っても続けたいときは `nohup ... &` か tmux の中で実行します。
3. できた `athena-diag-....tar.gz` を送ってもらう。

測っている間、サーバーには次のことだけをします。

- `jcmd` で GC のログを1つ追加し、終わったら外す（元々ある GC のログの設定はそのまま）。
- サーバーのディレクトリに `athena-diag.request` を作る。Athena 0317 以降は、それを見て 5 秒ごとに TPS・tick の時間・プレイヤー数・チャンク数を `athena-diag.csv` に書く。終わるとファイルは両方とも消える。
- `/proc` からプロセスの CPU 時間とメモリを読む。重い道具（`jstat` など）は使わないので、小さな VPS でも負荷はほぼない。

集めないもの：プレイヤー名、チャット、プレイヤーの IP アドレス、ワールドのデータ。設定ファイルは、パスワード・トークン・シークレット・アドレスを消してから入れる。**相手には、この内容を事前に伝えて了承をもらう。**

## 2. こちらでやること

```bash
python3 athena_diag_report.py athena-diag-arena1-20261018-120000.tar.gz
```

同じ名前の `.html` ができます。1つのファイルで完結していて、ネットにつながっていなくても開けます。

## 3. 提案を確かめる

レポートの「見込み」は、Athena の開発で計測した値です。相手のサーバーで同じになるとは限りません。

1. 同じ構成のサーバーが何台もあるなら、**1台だけ**提案どおりに変える。
2. その1台と、変えていない1台を、同じ時間帯にこのキットで測る。
3. 2つのレポートの数字（CPU、メモリ、フルGC、TPS）を並べて相手に渡す。問題がなければ、全台に広げる。

元に戻すときは、変えた設定や起動フラグを戻して再起動するだけです。

## 気をつけること

- Athena 0317 より前の版や、Athena 以外のサーバーでも動きます。ただし TPS とプレイヤー数は取れず、レポートにもその旨が出ます。
- 測る時間が短いと、フルGCが起きずに「GC後のヒープ」が実際より小さく見えることがあります。プレイヤーが一番多い時間帯を含めてください。
- `jcmd` はサーバーと同じユーザーで動かす必要があります。root で実行すれば、スクリプトが自動で切り替えます。
