# Athena の精査（全体） — 2026-11-24

## 対象と方法

- **対象**：`origin/master` `12e258e`（server 0456・api 0070）。パッチを当てたソース（`PandaSpigot-Server` の 0456）を読んだ。本番の sg2 と同じコード。
- **大きさ**：
  - Athena のパッチは 357 本、足した行は約 6 万 9 千行。うち約 3 万 3 千行は、名前を読みやすくする機械的な置き換え（0137）。
  - Athena だけのクラスは約 1 万 1 千行（`net.minecraft.server.Athena*` と `athena.server`）。
- **深く読んだ所**：
  - 外から届くデータを読む所：1.7 のクライアントのパケット（`AthenaLegacy17Decoder`・`AthenaLegacy17` の NBT）、圧縮を解く所（`PacketDecompressor`）、フレームを分けて一度に解く所（`PacketSplitter` の 0448）。
  - ワールドのスレッドの中心（`AthenaWorldThread`）と、ワールドを加える・抜く・取り戻す所（`WorldServer.athenaJoinThread` など）。
  - Athena の API の入り口（`AthenaServerImpl`）、少しずつのテレポート（`AthenaTeleportQueue`）、エンティティのスレッドで動かす所（`athenaRunForEntity`）。
  - コマンド（`/temptp`・`/disguise`・`/mask`・`/chatcolor`）。
  - Guard の当たりの確かめ（`AthenaGuard.attackOk`）と、過去の当たり判定の記録（`EntityPlayer.athenaRecordBox`）。
  - 飾りつけの係（`ChunkDecorationExecutor`）、ボットのログインと表（`PlayerList`）、ログを書く所（`log4j2.xml`、0307）。
- **見渡した所**：
  - static で変わる値を、`net.minecraft.server` の全部から探した。
  - 使っているライブラリの版。
  - 前の精査（10-31〜11-24 の 9 本）の、直していない項目が今のコードに残っているか。
- **本番で確かめた所**（VPS-B の sg2）：
  - 10-30 からのログ 108 本の警告・エラー・Guard の記録。
  - `athena.yml` の設定、AOT のキャッシュ、テンプレートのフレームのファイル、起動の台本。
- **読んでいない所**は最後に書いた。全部の行を読んだわけではない。

## まとめ

- **高**はない。
- **中**は 2 件。
  - M1：Guard が本番で、正直な人の当たりを消し、切っている疑いがある。遊んだ 4 人の全員が検出され、そのうち 2 人が計 12 回切られた。
  - M2：sg2 の AOT のキャッシュが、11-20 から、起動しただけの記録で作られている。
- **低**は 5 件。うち 4 件は、前の精査から残っているもの。
- 外から届くデータの読み方、ワールドのスレッドの受け渡し、API のスレッドの確かめ、コマンドの権限に、新しい問題は見つからなかった。

## 中

### M1 Guard が、正直な人の当たりを消し、切っている疑い（本番で有効）

- **本番の設定**：sg2 の `athena.yml` は `guard.enforce: true`・`kick: true`（30 秒に 5 回で切る）。10-30 から同じ。
- **本番の記録**（10-30〜11-24 のログ）：
  - 遊んだ人は 4 人（yu_ukey、Bell0142、Kurono、HaniwaCho）。4 人とも検出された。ボットは 1 回も検出されていない。
  - 当たりを止めたのは、reach が 85 回、aim が 19 回。11-07 に、yu_ukey が 8 回、Bell0142 が 4 回切られた。
  - 検出は、すべて 11-05 と 11-07 の回にある。人は 11-11・11-14〜16 にも入ったが、戦ったかは分からない。
- **aim（視線から 60 度より外れた当たりを止める）**：
  - 比べるのは、攻撃のパケットが届いたときのサーバーの向き（`player.yaw`、`AthenaGuard.java:841`）。
  - 1.8 のクライアントは、クリックの処理（攻撃のパケット）を、その tick の向きのパケットより先に送る。そのため、サーバーの向きは 1 tick 古い。
  - 素早く振り向いて殴ると、正直な人でも 1 tick に 60 度より多く回る。止めた 19 回は 60〜112 度だった。
- **reach（届く距離を越えた当たりを止める）**：
  - 相手の過去の当たり判定を見返す長さは `4 + (ping + 49) / 50` tick（ping 18 ms で 5 tick、`AthenaGuard.java:803`）。
  - 1.8 の画面で、ほかの人の位置はおよそ次の分だけ遅れて見える。合わせて約 6 tick と、見返す長さを 1 tick ほど越える。
    - サーバーが送るのは 2 tick ごと（`EntityTracker.java:67`）
    - 届くまでに約 1 tick（送るのは tick の終わり）
    - クライアントが位置をなめらかにつなぐのに 3 tick
  - 殴られて飛ばされている相手は、1 tick に 0.4〜0.9 ブロック動く。見返す長さが 1 tick 足りないだけで、その分だけ越えて見える。
  - 止めた 85 回の越え方：0.05 未満が 10、0.05〜0.15 が 13、0.15〜0.3 が 15、0.3〜0.6 が 20、0.6 以上が 27。相手はほとんどボットで、ボットは殴られると飛ばされる。
- **本当に不正だったのかは分からない**。上の見立ては、コードとログから考えたもので、再現はしていない。
- **直し方の案**：
  1. すぐにできること：直すまで、本番の `guard.kick` を false にする。当たりを止めるのも誤りなら、`guard.combat` を false にする（動きの確かめは残る）。
  2. aim：攻撃の前と後の、両方の向きで確かめる（次の向きのパケットが届くまで決めない）。どちらかで 60 度以内なら通す。
  3. reach：見返す長さを、送る間隔とつなぐ分だけ長くする（`4 + (ping + 49) / 50` を `7 + (ping + 49) / 50` ほどにする）。または、1 度目は止めずに記録だけにして、続けて越えたときだけ止める。
  4. 素早く振り向きながら殴る試験と、飛ばされている相手を殴る試験を足す（`AthenaGuard` の試験は、動きと ping の分の 2 つ（`AthenaGuardMovementTest`・`AthenaGuardLagTest`）で、`attackOk` を通るものはない）。

### M2 sg2 の AOT のキャッシュが、起動しただけの記録で作られている（運用）

- 今のキャッシュ（`/opt/mc/shared-cache/70cad39f4af1e391/athena.aot`）は、11-20 06:18:22 に作られた。
- 作った記録（`record-sg2.aotconf`）は、11-20 06:17 の自動の再起動から、06:18:08 に止められるまでの約 20 秒の回のもの（CPU 19.5 秒）。Java の更新でキーが変わり、その日の 1 回目の起動が記録の回になった。
- 試合を通して記録した前のキー（`88c6ad20`）と比べると、記録は 77.8 MB → 69.9 MB、キャッシュは 80.1 MB → 72.1 MB と、約 8 MB 小さい。試合で使うクラスが入っていないと見られる。
- **影響**：最初の試合で、クラスの読み込みとリンクが試合中に起きる。どれだけ遅いかは計っていない。
- **直し方の案**：
  - VPS-B の README の手順（sgbench3 で、本番と同じ jar と設定でボットの試合を 1 回流す）で、記録を取り直す。
  - 今後、Java の更新のあとに手で再起動するときも、同じことをする。
  - 自動の再起動は止めた（ArcanaServers #9）ので、こうなるのは Java を更新した日だけ。

## 低

### L1 終わりかけのワールドのスレッドに、ワールドが加わることがある（11-17 の C2、残っている）

- `AthenaWorldThread.runLeaves` は、最後のワールドを外すと `running = false` にする（`AthenaWorldThread.java:378`）。
- `athenaJoinThread` が確かめるのは `thread.isAlive()` だけ（`WorldServer.java:1699`）。その間に加わったワールドは、誰も tick しない。
- 起きるのは、抜けるのを待ちきれなかったワールドがあり、その直後に同じスレッドへ別のワールドを加えたときだけ。
- **直し方の案**：`join` を、`running` を見る同期の中で行う。終わりかけなら断る。

### L2 `UserCache` に同期がない（11-17 の C1、残っている）

- 名前で人を引く `getProfile(名前)` は、表を書き換え、知らない名前なら、呼んだスレッドで Mojang に問い合わせる。`save-user-cache-on-stop-only: false` なので、毎回ファイルにも書く。
- ワールドのスレッドから呼ぶと、ログイン（サーバースレッド）と同時に表を書き換えることがある。
- SG と AthenaHub は名前で人を引かない（`getOfflinePlayer` を呼ばない）ので、今は起きない。ボットは表に入れていない（`PlayerList.java:94`）。
- **直し方の案**：`UserCache` の読み書きを 1 つのロックで守る。ワールドのスレッドから、知らない名前で呼ばれたら警告を出す。

### L3 `NextTickListEntry.nextTickEntryID` が、同期のない static（11-17 の C3、残っている）

- 同じ時刻・同じ優先度のブロックの更新の順番が、入れ替わるだけ。

### L4 光が変わっても、セクションの版が進む（11-10 の F4、残っている）

- `setExtSkylightValue`・`setExtBlocklightValue` は `modCount` を進める（`ChunkSection.java:263・273`）。`Athena.readSectionTypeIds` の版も、それにつれて進む。
- 版はチャンクのパケットの控えを捨てる合図にも使っているので、光で進めるのは要る。SG の地形の控えが、光の変化でも 4096 個を読み直すだけ。
- **直し方の案**：ブロックだけの版を別に持つ。

### L5 本番の起動の台本が、Athena の台本より古い（運用）

- 本番の `/opt/mc/start-small.sh` は ArcanaServers の `common/start-small.sh` と同じ。Athena の `deploy/start-small.sh` とは、次の 3 つが違う。
  1. 本番は `--enable-native-access=ALL-UNNAMED` を渡さない。
     - Java 25 は、Netty が native のライブラリを読むたびに警告を出す（sg2 の起動のログに出ている）。
     - いずれの版の Java は断るようになる（JEP 472）。断られると epoll・io_uring が使えず、遅い NIO になる。
  2. 本番は、AOT のキャッシュを、いちばん新しい記録から作る（`ls -t`）。Athena は、いちばん大きい記録から作る（`ls -S`）。
  3. 本番は、新しい 3 つより古いキャッシュを、すぐ消す。Athena は 7 日間残す。別のサーバーが起動中に使っているキャッシュを消さないため。
- 今は sg2 の 1 台だけなので、2 と 3 の害は小さい。1 は、旗が変わると AOT のキーが変わるので、M2 の取り直しと一緒に入れるとよい。

## 確かめて、問題がなかった所

- **1.7 のパケット**：
  - 長さは、負か残りより長ければ断る。アイテムの NBT は、1.8 と同じ 50,000 の上限で読む（0273）。
  - 読みかけで失敗したパケットは、出しかけた分を捨てる（0336）。
- **圧縮を解く所**：
  - 解く量は、接続ごとに上限がある（毎秒 4 MiB、まとめて 8 MiB）。宣言した大きさにちょうど解けなければ断る。
  - 出力は、解けた分だけ伸ばす（10 バイトで 2 MiB を確保させられない）。
  - 一度に解く道（0448）も、同じ上限と同じ確かめを通る。読んだパケットは受信のバッファを持ち続けない（`PacketPlayInCustomPayload` は自分の配列に写す）。
- **ワールドのスレッド**：
  - 最後のワールドが抜けたスレッドも、残った仕事をサーバースレッドへ渡す（11-10 の F2 は直っている）。
  - 抜けるのを待ちきれなかったときも、止まるのを待ちきれなかったときも、ワールドは必ず持ち主へ戻る。
  - 投げたスレッドのワールドは、止めたままサーバースレッドが取り戻す。
- **API**：
  - ワールドの読み込みはサーバースレッドだけ。チャンクの固定・タイルの一覧・変装・マスク・ボスバーは、そのワールドのスレッドだけ（`AsyncCatcher.catchOp`）。
  - 先読みとテレポートは、どのスレッドからでも頼める。持ち主のスレッドへ回す。
- **少しずつのテレポート**：別のスレッドの人は、そのスレッドで移す。抜けた人や移った人も、必ず結果を返してから終わる（`athenaRunForEntity` は、ワールドを追いかけて必ず動かす）。
- **コマンド**：`/temptp`（`athena.command.temptp`、op だけ）、`/disguise`・`/mask`・`/chatcolor` は、どれも権限を確かめてから動き、受け取る値を確かめる。
- **飾りつけの係**：自分のスレッドを持つワールドは、係に回さずにその場で飾る。スレッドへ移る前に、そのワールドの残りを片付ける（`ChunkDecorationExecutor.flush(world)`）。
- **ボット**：`usercache.json` に入れない。同じ名前の人がログインしたら、ボットが譲る。
- **`Athena.readSectionTypeIds`**：登録のない状態番号は空気として返す（11-10 の F3 は直っている）。
- **ライブラリ**：Netty 4.2.19、Log4j 2.25.5、Gson 2.10.1、SnakeYAML 1.33、commons-lang3 3.19、commons-io 2.20。
- **本番のログ**：10-30 からのログ 108 本に、ワールドのスレッドの止まり・スレッドの違反の記録・Athena のエラーはなかった（Guard の記録は M1）。
- **CI**：master の Build は 11-16 から 6 回とも成功。
