# 送信の固定費（C1・C2）の計測と、B5（2026-11-11）

対象は `perf/review-2026-11-11`。比べたのは次の 3 つ。

| 名前 | 中身 |
|---|---|
| 変更前 | server 0433 まで（B5 の統計を止める設定を含む） |
| 変更後 | 変更前に、0434（タグのないアイテムの書き出し）と 0435（パイプラインの確認を 1 回の走査に）を足したもの |
| 変更後 + Unsafe | 変更後を、起動のフラグに `--sun-misc-unsafe-memory-access=allow` を足して動かしたもの |

## 計測の方法

- **場所**：VPS-B。sg2 は計測の間だけ止め、最後に起動し直した（接続は 0 人だった）。
- **SG**：本番の sg2 の jar（`8d7c82d6`）と設定。マップは Shady_Hollow、8 部屋、デュオ。
- **ボット**：ネットワーク越しのボット（`sgbot.py`）。Mac から ssh のトンネルで繋いだ。ボットは 192 体を用意したが、部屋の定員のため入れたのは 104〜112 体。
- **Java**：ヒープ 256M、Shenandoah、C1 のみ。本番の `start-small.sh` で起動し、AOT キャッシュはベンチ専用の場所に置いた。
- **回し方**：`vps_runs.sh`。変更前 → 変更後 → 変更後 + Unsafe を 2 巡した。
- **集計**：入れたボットの数が回ごとに違うので、Netty のスレッドの CPU を、運んだパケットの数（ボットが受けた数と送った数）で割った（`netstats.py`）。

## 内訳（変更前、JFR、1 ms ごとのサンプル）

- **Netty の重さ**：本物の試合では、Netty のスレッドがサーバーの CPU の約 25% を使う（0.174 / 0.690 コア）。
- **ボットだけの計測では見えない**：これまでの VPS の計測は、サーバーの中のボット（`AthenaBotPlayer`）で取っていた。このボットは接続を持たないので、Netty の負荷が映らなかった。

| 内容 | Netty の時間に占める割合 |
|---|---|
| C1：drain ごとのパイプラインの確認（`names()` と名前での検索） | 4.3% |
| C1：パケットの番号を引く処理（`getPacketId`） | 1.9% |
| C1：drain ごとの送信用の buffer の確保 | 3.0% |
| C2：放送される移動系のパケット（移動・向き・テレポート・頭の向き）の書き出し | 約 2.5% |
| アイテムを書き出すたびの、Spigot の ItemMeta の往復 | 0.6%（手元の 20 体の計測では 7%） |
| Netty が Unsafe を使わない経路（`PooledDirectByteBuf`。下を参照） | 8.2% |

## 判断

- **C1：入れた（0435）。**
  - drain ごとのパイプラインの確認を、context の連結を 1 回たどるだけにした。割り当てはない。
  - Netty の `io.netty.channel` パッケージに補助クラスを置いた。サーバーの jar は Netty を再配置していないので、同じパッケージとして読み込まれる。
  - 確かめる条件は前と同じ。試験では、プラグインの handler をサーバーの handler の間 3 か所に挟んだ場合と、挟んだあとで外した場合を見た。
- **C2：入れない。** 放送される移動系のパケットの書き出しは Netty の約 2.5% しかない。使い回すには、1 回目に書いたバイト列を控えて写す必要があり、その費用で得がほとんど消える。
- **アイテムの書き出し：入れた（0434）。**
  - タグのない（または空の）アイテムは、往復の結果が必ず「タグなし」になる。
  - 全 Item と data 値で、元の処理と同じバイト列になることを試験で確かめた。
  - 本物の SG では小さいが、チェストを開ける人の多い試合ほど効く。
- **Netty の Unsafe：本番のフラグの問題。**
  - Netty 4.2 は Java 25 以降で `io.netty.noUnsafe=true` を既定にする。`--sun-misc-unsafe-memory-access=allow` がない本番では、バッファの読み書きが ByteBuffer を経由する（手元で `hasUnsafe=false` と `true` を確かめた）。
  - Athena の `deploy/start-small.sh` には J02 でこのフラグを入れてあるが、本番の ArcanaServers の `start-small.sh` には入っていない。
  - 効き目は約 3% で、2 回の差としてはばらつきに近い。入れると AOT キャッシュのキーが変わる。
  - **2026-11-12：本番の ArcanaServers の `common/start-small.sh` の FLAGS に足した**（理由を書いたコメントも付けた）。まだ配っていない。次に起動したときにキーが新しくなり、最初の 1 回は記録の起動になる。
- **getPacketId**：以前、ClassValue に替えて遅くなった（P07）ので、そのままにした。

## B5（0433）

- `athena.yml` の `playerStatistics: false` で、プレイヤーの統計と実績を数えなくなる。既定は `true`。
- 統計を基準にしたスコアボードの objective は、今までどおり数える。
- 本番の SG は統計を保存せず（`stats.disable-saving: true`）、実績も告知しない。スコアボードは `dummy` だけ。
- ArcanaServers の `vps-b/sg1` と `vps-b/sg2` の athena.yml に `playerStatistics: false` を足した（コミットしていない。この版の jar を入れたときに効く）。
- 計測では、変更前と変更後の両方に B5 が入っているので、効き目はここには出ない。JFR では、実プレイヤーの統計の加算はサーバー側の 0.5% だった。
